# Kru-Hub — โครงระบบที่พัฒนาแล้ว

## Stack และ UI

React + Vite + Tailwind + Axios + Motion + Lucide + Socket.IO client; Express + Socket.IO + MySQL 8.4 utf8mb4; Three.js เตรียมไว้สำหรับเกม ไม่โหลดในหน้า dashboard

ใช้แถบเมนูด้านบน 6 หมวด (หน้าหลัก ตารางเรียน/สอน แผนการสอน ข้อมูลโรงเรียน บัญชีผู้ใช้ คลังสื่อ) และหน้าหลักที่เปิดงานหรือหมวดย่อยได้โดยตรง เก็บหน้าที่เลือกใน URL hash เพื่อย้อนกลับและเปิดซ้ำได้ ข้อมูลโรงเรียนแยกกลุ่มปี/ปฏิทิน บุคลากร/วิชา ชั้น/เวลา และนักเรียน โทนขาว/ชมพู/ทอง มี Dark mode และ reduced-motion หน้าจัดตารางแยกแท็บตารางห้อง ตารางครู และกำหนดวิชา/ครู ตารางทั้งสองมุมมองใช้แถวเป็นวันและคอลัมน์เป็นคาบ ส่วนตารางกว้างบนมือถือเลื่อนแนวนอนได้เพื่อคงความอ่านง่าย

## โครงไฟล์

- frontend/src/: App, Timetable, Management, Plans, PublicReview, PdfViewer, Media, Portal
- backend/src/: auth, data, timetables, documents, word, server
- shared/scheduler.mjs: กฎเวลา/คาบและตัวจัดตาราง ใช้ร่วมกับหน้าจอและ backend
- schemas/: migration แบบ version/checksum, lock ป้องกันรันซ้อน, สถานะ running/applied
- docker/: local เฉพาะ mysql-twiniiz ใน group docker พอร์ต 3309
- deploy/: VPS project kruhub, web/api/db, พอร์ต web localhost 8082, volume MySQL และ uploads แยกจาก keelek

## บทบาท

| บทบาท | สิทธิ์หลัก |
| --- | --- |
| Super admin | เพิ่มโรงเรียน สร้างผู้ดูแล และจัดการข้อมูลทุกโรงเรียน |
| School admin | ข้อมูลพื้นฐาน บัญชีบุคลากร/นักเรียน/ผู้ปกครอง ตารางทุกชั้น เผยแพร่ และเอกสาร |
| ครู/บุคลากร | ดูข้อมูล/ตารางโรงเรียน จัดตารางเฉพาะชั้นที่ได้รับมอบหมาย ส่งเอกสารตนเอง กำหนดเวลาที่ไม่ว่างตนเอง |
| ครูประจำชั้น | สร้างบัญชีนักเรียน/ผู้ปกครองได้เฉพาะนักเรียนในห้องที่รับผิดชอบ |
| นักเรียน | ดูตารางเผยแพร่ของตนเอง |
| ผู้ปกครอง | ดูตารางเผยแพร่ของนักเรียนที่เชื่อมกับบัญชี |
| ผู้ตรวจ QR | ดูเอกสารตามหมวดที่แชร์ ไม่มีสิทธิ์แก้ ลบ หรือ endpoint ดาวน์โหลดต้นฉบับ |

คลังสื่อใช้ได้เมื่อมี profile ครูที่เปิดใช้งาน (รวม super admin สำหรับการดูแล) สมาชิกบุคลากรที่ไม่ใช่ครูไม่ได้รับสิทธิ์เล่นสื่อ

## บัญชีและหลายโรงเรียน

Password hash ใช้ bcrypt; session token สุ่ม 256-bit เก็บเฉพาะ hash ใน DB, cookie HttpOnly/SameSite=Strict และ Secure บน production หมดอายุ 12 ชั่วโมง ทุก API ตรวจบัญชี/สมาชิก/โรงเรียนจริง ไม่เชื่อ school_id จาก client การเปลี่ยน/รีเซ็ตรหัส ปิดบัญชี และสิ้นสุดปีจะเพิกถอน session

ทุก write request ใช้ custom header และตรวจ Origin จำกัดความถี่ login มี must_change_password สำหรับบัญชีที่ generate ให้ Composite FK บังคับการอ้างอิงโรงเรียนเดียวกัน audit log บันทึกการแก้ข้อมูลโดยไม่เก็บรหัสผ่าน/ไฟล์เนื้อหา

Super admin แยกจาก membership; หมวดสังกัดแยกจากวิชาที่ครูสอนได้ ครูสอนได้หลายวิชา การย้ายปีปิดสมาชิกนักเรียน/ผู้ปกครองของปีเก่า เก็บนักเรียนและ enrollment history ไว้

## ตารางเรียน/สอน

คาบมีวัน (1=จันทร์) ลำดับ เวลาเริ่ม/จบ และภาคเรียน แต่ละห้องเลือกคาบที่เปิดสอนได้ การมอบหมายผู้จัดอยู่ในระดับชั้น/ภาคเรียน

Requirement มีห้อง/วิชา/ครู/คาบต่อสัปดาห์/เพดานต่อวัน ครูต้องถูกกำหนดว่าสอนวิชานี้ได้ ค่า daily_limit=1 ป้องกันซ้ำวัน ข้อยกเว้นคาบคู่ระบุเพดานต่อวันเพิ่มได้

Manual ล็อกคาบเสมอ Auto เก็บรายการ Manual และรายการล็อกไว้ ล้าง Auto เฉพาะห้องที่ผู้จัดมีสิทธิ์ การลากไปยังช่องที่มีวิชาเป็นการสลับ ตรวจครูทุกคน จำนวนคาบ เวลาที่ไม่ว่าง และช่วงเวลาทับซ้อนก่อนบันทึก transaction เดียว Manual แบบอิสระผ่อนเพดานต่อวัน แต่ไม่ผ่อนครูชน/คาบห้อง/จำนวนคาบ

ลงวิชาเดียวกันหลายห้องพร้อมกันใช้ transaction เดียว ครูต้องไม่ชนกัน หากผิดเงื่อนไขห้องใดจะไม่บันทึกทั้งชุด

หนึ่ง version ครอบคลุมโรงเรียนในภาคเรียนเดียวกัน จึงตรวจครูข้ามชั้นได้ มี optimistic revision และ row lock ป้องกันการแก้ทับ Unique constraint กันคาบห้อง/ครูซ้ำ Auto รัน worker พร้อมเวลาจำกัด ใช้การเลือกงานที่มีตัวเลือกน้อยและลองหลายรูปแบบ ไม่รับประกันคำตอบสมบูรณ์ทุกกรณี เมื่อจัดไม่ครบเก็บผลบางส่วนและแสดงจำนวนคาบที่เหลือให้ Manual ต่อ

ก่อน Auto ตรวจ quota ห้องตรงจำนวน slot และความเป็นไปได้ของการกระจายวัน ก่อนเผยแพร่ต้องครบทุกห้องในปี/ภาคเรียน เผยแพร่ได้เฉพาะผู้ดูแลโรงเรียน มี unique published version ต่อ school/term ฉบับเดิม archived สร้างร่างใหม่คัดลอกฉบับเผยแพร่ ครูทุกคนในโรงเรียนดูตารางได้ และ export CSV รองรับไทย พร้อมป้องกัน spreadsheet formula injection

## เอกสาร

PDF, Word .docx, PNG/JPEG ขนาดไม่เกิน 20 MB ตรวจ signature จริง ไม่เชื่อ MIME อย่างเดียว ไฟล์ใช้ชื่อสุ่มนอก public directory เก็บใน persistent volume และ metadata ใน MySQL การส่งแผนระบุผู้ส่ง วิชา ชั้นปี ภาคเรียน วันที่แผน และ timestamp ส่ง

ปฏิทินอิงวันที่แผน รายการแสดงวันส่ง กรองหมวด/ชั้น/ครูได้ สถานะครูหมายถึงมีเอกสารในเดือนนี้หรือยัง ไม่มีตารางกำหนดส่งจึงไม่อ้างว่าขาดส่ง/ส่งช้า

PDF ใช้ PDF.js render เป็น canvas; Word preview แสดงข้อความเนื้อหา ไม่รักษารูป ตาราง หรือรูปแบบหน้าเอกสาร ดาวน์โหลดต้นฉบับภายในโรงเรียนเพื่อดูรูปแบบเต็ม ZIP ของ Word จำกัดจำนวน entry/ขนาดข้อมูล ยกเลิกการอ่าน XML DOCTYPE และไม่ตีความ preview เป็น HTML รองรับ .docx ไม่รองรับ .doc รุ่นเก่า

QR ใช้ token สุ่มเก็บ hash จำกัดหมวด วันหมดอายุ 1–30 วัน และเพิกถอนได้ ครูแชร์ได้เฉพาะหมวดตนเอง ผู้ดูแลแชร์ทุกหมวดได้ ลิงก์ดึงเอกสารในขอบเขตแบบดูอย่างเดียว ไม่มีการเปิด directory ไฟล์ต่อสาธารณะ Word ภายนอกได้รับเฉพาะข้อความ preview; PDF/รูปต้องรับข้อมูลภาพเพื่อแสดงผล จึงป้องกันการบันทึกภาพ/ข้อมูลจาก browser ทั้งหมดไม่ได้

## สื่อการเรียนรู้

มี catalog schema, หน้าสตูดิโอ, ค้นหา/กรองรายวิชาและชั้นปี และ modal เปิดไฟล์ใน /games/ ผ่าน iframe sandbox ยังไม่มีเกมจริงตาม spec และยังไม่มีหน้าจัดการ catalog สำหรับผู้ดูแล การลงเกมจริงเป็นงานขั้นถัดไป

## เวลาและ Deploy

DB เก็บ timestamp UTC, driver อ่าน UTC, UI แสดง Asia/Bangkok วันที่ปฏิทินใช้ DATE และเวลาในตารางประจำสัปดาห์ใช้ TIME ปี พ.ศ. เป็นค่าของปีการศึกษา ไม่ใช้วันที่ข้อความไทย

Deploy มี volume uploads เพื่อเก็บไฟล์สำคัญ Backup หยุด web/API ชั่วคราวเพื่อให้ snapshot DB และไฟล์สอดคล้องกัน แล้วเปิดบริการเดิมกลับ Update สำรอง → pull ff-only → build → หยุดบริการ → migrate → up พร้อม health check ถ้า migration ล้มเหลวให้บริการหยุดเพื่อกู้คืนอย่างมีแผน ไม่เปิดโค้ดเก่ากับ schema ใหม่อัตโนมัติ

## การตรวจสอบและขอบเขต

มี unit/integration tests สำหรับ tenant FK, session/สิทธิ์, teacher conflicts, manual locks, free mode, partial Auto, bulk rollback, ย้าย/เผยแพร่/export, PDF/รูป/Word upload, QR revoke, ครูประจำชั้น/ผู้ปกครอง และ academic rollover

ตรวจ local UI, responsive/Dark, API/MySQL และ Docker build แล้ว ยังไม่ได้ deploy/restore บน VPS จริง ไม่มีเกม เช็คชื่อ หรือการบ้าน (สองอย่างหลังเป็นแนวทางอนาคตใน spec) ยังไม่ได้ใช้กับข้อมูลโรงเรียนจริงจำนวนมากหรือทดสอบโหลดพร้อมกันหลายโรงเรียน

## รายวิชาและชุดวิชาตามระดับชั้น

`subject_grades` ผูกวิชากับหลายระดับชั้น หากไม่มีรายการถือว่าใช้ได้ทุกชั้นเพื่อรองรับข้อมูลเดิม หน้ารายวิชามีตัวกรองชั้น หน้ากำหนดวิชาห้องและส่งแผนแสดงเฉพาะวิชาของชั้นที่เลือก Backend ตรวจความสัมพันธ์ก่อนสร้าง requirement หรือแผนใหม่ ประวัติเดิมไม่เปลี่ยน

`grade_curriculum` เก็บรายวิชา คาบต่อสัปดาห์ และสูงสุดต่อวัน แยกโรงเรียน/ภาคเรียน/ชั้น ผู้ดูแลตั้งชุดผ่าน ตารางเรียน/สอน → กำหนดวิชาและครู → ชุดวิชาประจำชั้น แล้วเลือกหลายห้องและครูแยกแต่ละวิชา/ห้อง การ apply ทำใน transaction และล็อกภาคเรียน ตรวจชั้น/ปี ครูที่สอนวิชาได้ และผลรวมไม่เกินคาบของห้อง หากผิดยกเลิกทั้งชุด เพิ่มเฉพาะวิชาที่ยังไม่มี ไม่เขียนทับวิชา/ครู/คาบเดิม แก้ชุดภายหลังไม่เปลี่ยนห้องที่เคยนำไปใช้โดยอัตโนมัติ

หน้ารายการวิชาห้องแสดงยอดรวมคาบวิชาเทียบจำนวนคาบเปิดสอน แก้ครูและจำนวนคาบแยกห้องได้สำหรับวิชาที่ยังไม่มีรายการในตารางทุกฉบับ โดยคงข้อมูลที่มีตารางและประวัติแล้วไว้ ก่อนจัด Auto ต้องกำหนดจำนวนคาบรวมให้เท่ากับคาบเปิดสอน

## เตรียมเวลาเรียนและห้องเรียนให้เร็วขึ้น

ชั้นปีมี `abbreviation` เช่น ป.5 ฟอร์มไม่ให้กรอก sort_order แล้ว ระบบเพิ่มลำดับท้ายรายการอัตโนมัติและอ่านตาม sort_order/id ชั้นเดิมเว้นตัวย่อไว้จนผู้ดูแลระบุเอง ไม่มีการเดาตัวย่อหรือเปลี่ยนชื่อห้องย้อนหลัง

ห้องใหม่เลือกปี/ชั้นแล้วกรอก `room_number` เช่น 1 Backend สร้างชื่อจากตัวย่อเป็น ป.5/1 และตรวจว่าชั้นอยู่ในโรงเรียนเดียวกัน ห้องเดิมที่ไม่มีเลขห้องยังใช้ชื่อเดิมได้ หากต้องการเปลี่ยนเป็นรูปแบบใหม่ต้องเลือกในฟอร์มเอง การแก้ห้องที่มีตารางแล้วถูกป้องกันตามกฎเดิม

เวลาเรียนใช้ปุ่ม “เพิ่มเวลาเรียนหลายวัน” เลือกได้ จันทร์–อาทิตย์ พร้อมชุดเวลา 1–12 คาบและเลขคาบเริ่มต้น มีปุ่มเพิ่มคาบเดียวต่อจากคาบเดิมกับชุดตัวอย่าง 5 คาบ ระบบสรุปจำนวนวัน × จำนวนคาบก่อนบันทึก `/week` ยังคงรองรับ request เก่าที่ไม่ส่ง days (จันทร์–ศุกร์) เพิ่มในภาคเรียนที่มีคาบได้ ข้ามเฉพาะเลขคาบและเวลาที่ตรงกันทั้งหมด ถ้าเลขซ้ำแต่เวลาต่างหรือช่วงเวลาทับกันจะ rollback ทั้งชุด ไม่เขียนทับคาบที่อ้างอิงในตารางแล้ว การเพิ่มเวลาเรียนไม่เพิ่มคาบเปิดสอนของแต่ละห้องโดยอัตโนมัติ ให้กำหนดผ่าน “คาบของห้อง” ตามเดิม

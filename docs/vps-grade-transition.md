# อัปเดตครั้งแรกเป็นระบบจัดตารางรายชั้น

แผนที่ผู้ใช้ยืนยันจาก snapshot วันที่ 26 ตุลาคม 2569:

- โรงเรียน 1 ภาคเรียน 1: ป.5 (ชั้นปี 8) จากฉบับ #3 จำนวน 125 คาบ เป็นจัดเสร็จแล้ว
- ป.4 (ชั้นปี 7) จากฉบับ #4 จำนวน 125 คาบ เป็นกำลังจัด
- รวมทั้งสองชั้นในตารางกลางใหม่ โดยรักษาครู ตำแหน่งคาบ และสถานะล็อกเดิม ต้นฉบับทุกชุดยังอยู่

รันบน VPS สำหรับการเปลี่ยนระบบรอบนี้:

```sh
cd /srv/apps/kruhub
git pull --ff-only origin main
COMPOSE_PARALLEL_LIMIT=1 sh deploy/scripts/update-grade-workflow.sh
```

สคริปต์ตรวจต้นฉบับ จำนวนคาบ ความครบของ ป.5 และครูชนก่อนเริ่ม สำรองฐานข้อมูลกับ uploads ผ่านสคริปต์เดิม จากนั้น build และหยุดเฉพาะ Kru-Hub เพื่อเช็กซ้ำว่าข้อมูลไม่เปลี่ยน ก่อนรัน migration และรวมตารางใน transaction เมื่อสำเร็จจึงเปิด Kru-Hub และรอ health check ไม่มีคำสั่งหยุดหรือแก้ Keelek

หากข้อมูลเปลี่ยนระหว่างเตรียม จะหยุดก่อน migration และเปิด container Kru-Hub เดิมกลับมา หาก migration/การรวมล้มเหลวหลังเริ่มเปลี่ยน schema จะคง Kru-Hub หยุดไว้ให้ตรวจ logs/backup ไม่เปิดระบบที่ย้ายไม่ครบ

รายงานจะอยู่ใน `backups/grade-transition-*.preflight.json` และ `*.result.json` การรันซ้ำทันทีไม่สร้างตาราง/คาบซ้ำ หากมีการแก้ตารางใหม่หรือสถานะจัดเสร็จเปลี่ยนแล้ว สคริปต์จะปฏิเสธการรันซ้ำเพื่อไม่ย้อนทับงานใหม่

หลังเปลี่ยนระบบสำเร็จ การอัปเดตรอบถัดไปใช้ `sh deploy/scripts/update.sh` ตามปกติ ไม่ใช้สคริปต์เปลี่ยนระบบซ้ำ

ตรวจหลังอัปเดต:

```sh
sh deploy/scripts/compose.sh ps
curl --fail https://kruhub.twiniiz.com/api/health
curl -I https://keelek.kuayrai.com/
```

ตรวจในหน้าตารางว่า ป.5 ขึ้นจัดเสร็จแล้ว 125 คาบ และ ป.4 ขึ้นกำลังจัด 125 คาบ ก่อนให้ผู้จัดตารางทำงานต่อ
